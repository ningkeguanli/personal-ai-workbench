# 个人AI工作台 V3.6.3｜云端Web应用阶段验收修复版（工程源代码）

> 这是 **可部署的 Next.js + PostgreSQL 工程起点**，不是单机HTML原型。正式部署需要你自己的云主机/应用托管与 PostgreSQL 服务。目前尚未部署在线地址。

## 已覆盖

- 个人密码登录（签名 HttpOnly Cookie）；业务接口均验证登录与跨站来源。
- 云端 PostgreSQL 数据持久化：客户、联系人/商机模型、任务、沟通原文、项目、候选版本与有效版本、AI分析、业务与训练任务、后续验证。
- 工作首页：真实数据库查询、任务创建及完成、近期客户与项目。
- 客户列表/详情：创建客户、创建商机、记录沟通、按业务或个人能力目的启动真实AI分析、查看证据与限制、人工确认建议并生成任务、记录下一次实际反馈。
- 项目列表/详情：新建项目、项目任务、保存候选版本、显式确认为有效版本（不自动覆盖）。
- 全局查找：客户、项目和任务名称。
- 资料与成果、成长：显示真实建设状态，**尚未完整开发**，但在完整产品基线中保留。

## 技术构成

- Next.js 15 App Router、React 19、TypeScript
- PostgreSQL（可托管在 Supabase、Neon 或其他支持 PostgreSQL 的平台）
- 原生 pg 服务端驱动，SQL参数化，事务控制
- AI 服务端调用 Responses API，可通过 `OPENAI_MODEL` 配置模型；未配置密钥明确报错，不返回模拟AI结论
- 自有HMAC会话签名，适合单人初期使用；未来可替换为托管认证服务

## 快速启动

1. 运行环境：Node.js 20+、npm、PostgreSQL 15+；仅首次安装依赖及部署需要网络。
2. 复制 `.env.example` 为 `.env.local`（**不要把密钥放到前端或 Git**）。
3. 设置：`DATABASE_URL`、`APP_PASSWORD`、`APP_SESSION_SECRET`。
4. 如果使用本地 PostgreSQL 开发，可先设置 `POSTGRES_PASSWORD=你的本地密码`，执行 `docker compose up -d`。然后使 `DATABASE_URL` 中的密码与其一致。
5. 执行 `npm install`，接着运行 `npm run db:migrate`。注意 `db:migrate` 脚本读取进程环境变量；`.env.local` 不是 Node 自动加载，运行脚本前请将 `DATABASE_URL` 导入 shell（例如 `export DATABASE_URL='...'`）。
6. 执行 `npm run dev`，访问 `http://localhost:3000` 登录。
7. 生产环境部署：将环境变量配置在云应用托管中，使用托管 Postgres 数据库，并确保应用有HTTPS域名及数据库定期备份。构建命令为 `npm run build`，启动命令 `npm run start`。

云端正式运行时无需使用本地浏览器保存客户和项目：所有正式数据进入PostgreSQL。

## AI分析使用条件

- 配置服务端 `OPENAI_API_KEY` 才能启动真实AI分析。
- `OPENAI_MODEL` 默认仅为示例模型名；请按你的账号支持的模型和成本调整。
- 当前处理文字与已完成的录音转写。**原始音频上传、自动转写、多文件知识检索尚未接入**。
- 调用前会提供本次沟通、最近相关沟通、已关联商机信息。
- 返回业务与能力两类结构化观察，均为**待确认建议**。
- **没有任何接口会根据AI建议自动更改商机正式阶段。**
- 采纳业务行动或个人训练时，分别创建关联任务；同一诊断采纳操作采用行锁和唯一约束防止重复动作。
- 后续验证由用户填写真实观察，**必须关联原沟通之后实际发生的同一客户沟通**；不因客户没回复就认定个人能力差。

## 部署前的必要检查

- 使用独立高强度 `APP_PASSWORD`（12字符以上）和随机 `APP_SESSION_SECRET`（至少32字符）。
- 生产域名必须启用HTTPS；避免公共网络明文传输。
- PostgreSQL 应使用独立应用账号、最低权限、托管备份，连接串与密码只放服务端环境变量。
- 实际部署前建议增加登录频率限制、密钥轮换机制、进一步完善数据库迁移自动校验、请求大小及耗时控制和异步AI任务队列。当前项目属于第一阶段工程基础，并非无需进一步加固即可公开部署的最终成品。
- 对长篇原始录音转写，目前沟通与项目正文提交上限分别为200万字符，**超限会明确拒绝，不会截断保存**。真实AI单次分析支持最多12万字符，更长的文本完整保存但不会冒充已分析全文；仍需后续接入异步分段分析与对象存储。

## V3.6.1 纠偏说明（相对 V3.6）

- **正文不静默截断：** 沟通转写和项目版本正文在支持上限内保留原始字符与换行；超限返回 `413 INPUT_TOO_LONG`，不写入截断内容。当前文字提交上限为200万字符，实际云托管请求体限制可能更低，正式支持大文件需对象存储及分块上传。
- **AI不会伪装全文分析：** 删除只发送前50,000字符的做法。单次文本超过120,000字符返回 `422 AI_INPUT_TOO_LONG`，不生成局部结论；未来仍需完善分段、异步与任务队列。
- **发生时间：** 客户沟通表单可填写实际日期时间，浏览器转换为带时区ISO值提交；历史分析只读取目标沟通发生时及之前的资料。若商机当前记录更新晚于目标历史沟通，不作为当时的阶段快照。
- **业务与训练反馈关联：** 验证必须选择另一条实际后续沟通；服务端和数据库均检查客户归属与时间顺序，冲突商机不得错误关联。旧版未绑定沟通的验证记录保留并显式标为待补关联。
- **项目完整性：** 项目可关联客户或商机；新增关联一致性约束，正式有效版本在数据库层必须归属于当前项目。
- **分页与长历史：** 客户、项目、沟通、行动、项目任务、版本列表采用服务端分页；沟通全文与历史版本正文按需请求，避免页面批量载入长文本。
- **能力观察基础记录：** 采纳有证据的训练建议时生成`ability_observations`，后续验证记录更新单次实践状态；成长页面展示近期观察，不将其误称长期能力评分。
- **已有功能：** 继续保留V3.1所定义的98项功能和双闭环规划；本次不增加新的独立导航模块。
